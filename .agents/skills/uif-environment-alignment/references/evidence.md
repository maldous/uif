# Scoped evidence matrix

Bind the selected existing issue, role, executor, operation and source before
collecting evidence. A record may cover only one operation or executor; do not
carry another host's paths, authentication or toolchain into it as verified facts.

| Category | Useful real evidence | Limit or scoped failure |
| --- | --- | --- |
| Source | Actual checkout root, repository, accepted/task refs, commit/tree, preserved dirty/divergent work, authenticated remote read | Local tracking refs or an export do not prove remote currency, clone authentication or live deployment. |
| Instructions | Applicable root/nested AGENTS, selected policy/manifest/profile version and hash, actual readable path and executor acknowledgment | Published guidance is not startup installation, automatic discovery or runtime enforcement. Preserve later directions and report drift. |
| Custody/recovery | Existing owner, task generation, coordinator epoch where required, original intent/receipt and checkpoint compatibility | A pause, no running tasks, missing session or null assignee cannot release a claim or authorize replay. |
| Git/authentication | Actual local commit capability, supported authenticated read/publication route and selected repository scope | Read, local commit, native push and connected-app publication are separate. Never borrow or create credentials just for this check. |
| Skills/plugins | Actual source/version/digest, file access, catalog discovery and safe invocation where useful | Impeccable for visual work; repository-docs-review for repository documentation; Context7 for external library docs. Optional absence does not stop unrelated work. |
| Provider operations | Existing Cloudflare/Netlify configuration, actual tool/schema, account/site and permission for selected action | A connector identity or installed CLI does not prove every operation's scope, CLI authentication, entitlement or publication custody. |
| Toolchain/dependencies | Project-pinned versions/locks and allowed setup for this executor | Do not upgrade pins, install arbitrary packages or conflate ambient binaries with the selected isolated runner. |
| Deterministic checks | Deployed helper catalog/hash, exact branch/full expected commit/tree, declared target/setup, resource bounds and terminal inner receipt | Draft helpers and submitted jobs are not deployed capability or passed checks. Unsupported lint/build/deploy stays explicit. |
| Product constraints | Selected project's actual requirements, data/rights/privacy, review and destination/release conditions | Environment readiness is not full functional, security, browser, release or product compliance. |

## Scope the decision

- **Source preparation/read-only investigation:** verify accessible source,
  applicable instructions, actual scope and preservation/custody boundaries.
  Missing production deployment credentials or an unused design engine is not a
  preparation blocker. A denied read remains denied; do not use another route
  for the same withheld transfer.
- **Build/test execution:** additionally verify the actual supported executor,
  exact source, toolchain/dependencies, setup grant, target and resource admission.
  Use existing check receipts where their source/profile/contract is unchanged.
- **Integration/publication:** additionally verify current sole writer, exact
  accepted source/artifact, review, consuming destination/permissions and original
  effect recovery at the actual boundary. Do not infer publication from builds.
- **Mode/ownership transition:** additionally verify surviving operations,
  current ownership and fencing, compatible checkpoint, receiver acknowledgment
  and destination capabilities actually consumed. The reusable check does not
  implement the off-Foo authority or session lifecycle. Unknown authority holds
  only actions requiring it; independent already-owned preparation may continue.

For each failure name the affected operation and smallest supported corrective
step. Explicitly mark not-run, unsupported, inapplicable and uncertain outcomes.
Do not convert absence of evidence into success or create a universal green/amber
score that hides these distinctions. Keep evidence in the existing Linear issue
and original private receipts, not a replacement cross-project delivery tracker.

## Project selection and useful reuse

The product delivery matrix is UIF, OffMenu, ANQR, CircularQuay and CIX. Cloud is
an infrastructure/provider role with its explicit assigned repository and site
custody, not an invented sixth product compliance gate. Revalidate current source
profiles: develop is normal, CQ's bootstrap exception and Cloud's actual baseline
must be established from current records. CIX product and private operations are
separate source/disclosure surfaces of one role.

A transition/on-demand review can reuse an earlier immutable test, review or
artifact without rerunning it. Re-observe facts that could have changed and
matter now: current branch/custody, destination, deployment/catalogue, auth scope,
allowance and capacity. A reused test is not fresh runtime evidence. Never replay
uncertain or denied effects under a new identity, and never close a whole issue
from an accepted bounded contribution alone.
