# UIF environment alignment

Use one evidence procedure across UIF, OffMenu, ANQR, CircularQuay, CIX and the
assigned Cloud infrastructure role. The categories are uniform; applicable
requirements, source baselines, tools and permissions remain project-specific.
This skill grants no access, claims, mode transition, installation or publication.
It is an evidence workflow, not an installed runtime fence or a second controller.

## Select the consuming operation

Identify the existing Linear issue, responsible role, actual executor, current
mode and next operation: source preparation, deterministic checks, integration,
publication or a mode/ownership transition. Read [the evidence matrix](references/evidence.md)
for required facts and operation-specific limits. Use the project's existing
report schema; do not create another intake queue, status ledger or release gate.

Read current applicable AGENTS.md, nested instructions, selected environment
policy/manifest/profile and original operation/checkpoint records. Bind each to
its actual source and timestamp. Later user directions control; record a stale
instruction/profile conflict and correct it through its owner, without silently
changing permissions or treating old prose as a permanent stop on independent work.

## Collect only useful missing evidence

1. **Source and custody.** Verify repository, accepted baseline, task branch,
   immutable commit/tree and local dirty/divergent work. Verify remote state
   through an available authenticated route. Preserve unique files, old refs and
   original effects; use an isolated destination rather than reset/clean. A
   reconstructed snapshot, shallow Git repository and authenticated clone are
   different evidence. Read current issue scope and preserve actual claims,
   publisher custody and explicit holds; null assignees are not a claim failure.
2. **Directives and skills.** Record what the executor actually read, including
   policy version/digest and selected project instructions. Check file access,
   automatic skill discovery and successful engine execution separately. Use
   repository-docs-review for documentation when available; use applicable
   Impeccable guidance for visual work. A missing optional skill does not block
   unrelated backend work. Do not install, upgrade or enable tools merely to
   produce a green row; route a real distribution gap to its existing custodian.
3. **Tools, authentication and dependencies.** Verify actual tool names/schema,
   destination/project/account scope, language/toolchain pins, locked dependencies
   and shared resource admission required by this operation. Native Git and a
   connected GitHub app, MCP and local inference, CLI presence and authenticated
   provider access are separate capabilities. Context7 is for applicable external
   library documentation, not private-repository correctness or a source-upload
   destination; use official upstream documentation when appropriate. Cloudflare
   and Netlify need their actual project configuration and operation scope only
   where selected. Do not expose secrets or broaden grants to repair a gap.
4. **Actual checks.** Reuse accepted checks at still-valid exact bindings. Run only
   missing or affected checks needed for this unit, not ceremonial product suites.
   For Foo branch execution, read the deployed project_checks schema/catalog,
   verify the published branch and full expected commit, then follow its original
   discover/run/status receipts. The shared foo-project-checks skill may supply
   that workflow when present; otherwise use the actual deployed contract.
   Unsupported targets remain unsupported, never fabricated commands. A helper
   snapshot does not update the owner's checkout or prove a full product gate.
5. **Evidence and next action.** Distinguish submitted, running, terminal outcome,
   source review, publication, merge, installation and useful runtime behavior.
   Record exact source/target/operation/receipt and narrowly scoped failures in
   the existing issue. Preserve private logs in their original custody. Collect
   prospective telemetry with real call start/end and outcome, never inferred
   intervals or private payloads. Do not create calls solely to animate a graph.

Use existing White Room inventory/comparison tools when their declared target and
source are applicable. Their supplied-evidence pass is not authentication or
execution authority. Null expectations, unknown discovery, expired ownership or
unreconciled effects remain explicit. Do not invent data to make a comparator pass.

## Quota and Morgan MCP transitions

Run this same procedure on the destination at each supported transition, including
replacement/recovery, not only on first startup. Reconcile surviving source,
claims, original operations and compatible checkpoints before the first
unaccepted stage. A quota reset is not readiness and a missing session is not
proof that its effects stopped. Hard quota, authentication, network/namespace,
rate limits and task failures have distinct diagnoses.

Keep user pauses and current cloud allocations effective. Validate actual current
ownership/generation/epoch and supported effect fences where the consuming action
requires them; this skill cannot acquire or transfer them. During a Foo outage,
continue independent cloud work through its actual available dependencies. Apply
the selected sustained-failure grace and original-operation recovery before any
ownership-changing failover, rather than using a single failed probe as takeover.
For local return, retain active cloud owners and use fresh allowance/admission
and the selected per-issue checks; never revive every old session.

## Deliver the result and continue

Give a concise per-operation matrix: verified facts and receipts, inapplicable
requirements with reasons, and missing/failed/unsupported/uncertain facts with the
specific affected operation and next owner/action. Reuse existing typed statuses.
State separately what remains unverified about full product compliance, runtime
installation and autonomous BAU. The workflow itself does not grant those results.

An unmet optional capability or one project's failure is not a blanket hold on
other projects or operations. Continue genuinely eligible work and refill through
the existing owners. A genuine claim, rights, security, source or unknown-effect
restriction still blocks its dependent effect. Do not substitute a narrower
outcome for the user's requested delivery or quietly remove a real requirement.
