# UIF agent instructions

UIF owns shared infrastructure and cross-project operating controls. Linear is
canonical for current work, scope, ownership, dependencies and acceptance.
Historical README scopes are provenance, never another intake queue.

For post-reboot collaborative subtask creation, follow the owner's
[current creation rule](docs/agents/startup-template.md#collaborative-subtask-creation):
request GPT-6.2 Sol at the highest supported effort (currently
`model: "gpt-6.2-sol"`, `reasoning_effort: "ultra"`). This supersedes the older
GPT-6.1 Sol preference only for newly created collaborative subtasks. It does not
change the main model, existing workers or ordinary Foo/native session policy.
Record requested versus actually observed settings; do not launch a worker just
to prove the setting or resume processing while the owner's pause is effective.

At startup read the [operating policy](docs/agents/uif-worker-policy.md),
[version/digest manifest](docs/agents/uif-worker-policy.json) and your selected
[environment/project profile](docs/agents/environment-profiles.json). Pass the
actual policy digest, task/source, owned paths, executor and original operation
identities to children; verify their acknowledgements. Project and nested
instructions retain product, toolchain, privacy, review and publication authority.

Read the [dated cloud-owner process checkpoint](docs/agents/cloud-owner-process-exercise-2026-11-16.md)
for bounded verified examples; it does not replace the policy or prove BAU.

In Morgan MCP mode, existing project agents reason in their own Cloud sessions,
use their Cloud workspaces first and call supported deterministic MCP where work
requires it. Zero Foo quota is not a prerequisite; Foo-local Codex is not
required. Native pauses, execution claims and publisher authority remain intact;
an orchestration receiving acknowledgment is not a claim transfer or fence.

Use the [environment alignment skill](.agents/skills/uif-environment-alignment/SKILL.md)
at startup, on demand and at quota/Morgan MCP transitions to collect real
operation-scoped readiness evidence. It does not create a blanket project gate
or prove product compliance.

Use [the operating procedure](docs/operating-procedure.md) for execution or mode
changes. Before startup, transfer, quota recovery, replacement or interruption
recovery, read the complete [white-room recovery contract](docs/white-room/startup-and-recovery.md)
and [existing executable comparison/reconstruction guidance](docs/white-room/README.md).
Reuse accepted stages, current remote source and compatible checkpoint/operation
evidence; preserve dirty work and custody. A quota reset or a green comparator
never grants a claim, replays a session or authorizes publication.

The required normal state is unattended continuous BAU without this chat.
Stokowski coordinates local-ready mode; an independently durably scheduled
logical Morgan lifecycle appoints/reconstructs failed coordinator/project
executions through atomic epochs and effect fences. Native Linear is sole
intake. The shared election/claim authority must remain reachable independently
of Foo/MCP so eligible cloud work continues through actual project dependencies.
The off-Foo authority and independent scheduling/session-control adapters are
currently unimplemented/unqualified; local source tests are not deployment proof.
Do not select a storage platform/provider or invent an installed endpoint here.

Foo/MCP ownership-changing failover uses a configurable default 15-minute
sustained failure grace with multiple qualified probes and healthy-probe reset.
Hold unsafe dependent admission during uncertainty, reconcile the original
operation and continue independent work. Hard quota closes dependent model
admission immediately. If all reasoning is unavailable, preserve state, continue
independent deterministic work and resume automatically on existing authorized
capacity; no new provider or spending. An explicit user stop/pause remains
effective across every recovery. The 64-local-session ceiling shares host
resources with MCP work; restore local admission gradually per issue without
stealing active cloud ownership.

Before Foo access read [current Windmill routing](docs/agents/windmill-workspace.md).
Cloud checkouts are isolated from Foo and from other workers. Use actual tools,
grants and shared resource admission; root transport does not imply repository
commands should run as root. Never bypass denied access through another route.

Use the [managed supervision skill](.agents/skills/uif-supervision/SKILL.md) for
service reports and supported controls. Keep project-specific skill/plugin
capabilities and [memory routing](docs/agents/memory-routing.md) scoped. Load
historical adoption/source records only for their applicable evidence, preserving
current holds and accepted work. Publishing documentation is not runtime
installation or successful delivery. Complete the authorized integration,
qualification and supported controlled start without a separate approval
checkpoint for that same outcome; report actual installed/readback evidence and
remaining gaps. Preserve applicable platform requirements and specific holds.
