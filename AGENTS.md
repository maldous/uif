# UIF agent instructions

UIF owns shared infrastructure and cross-project operating controls. Linear is
canonical for current work, scope, ownership, dependencies and acceptance.
Historical README scopes are provenance, never another intake queue.

At startup read the [operating policy](docs/agents/uif-worker-policy.md),
[version/digest manifest](docs/agents/uif-worker-policy.json) and your selected
[environment/project profile](docs/agents/environment-profiles.json). Pass the
actual policy digest, task/source, owned paths, executor and original operation
identities to children; verify their acknowledgements. Project and nested
instructions retain product, toolchain, privacy, review and publication authority.

Use [the operating procedure](docs/operating-procedure.md) for execution or mode
changes. Before startup, transfer, quota recovery, replacement or interruption
recovery, read the complete [white-room recovery contract](docs/white-room/startup-and-recovery.md)
and [existing executable comparison/reconstruction guidance](docs/white-room/README.md).
Reuse accepted stages, current remote source and compatible checkpoint/operation
evidence; preserve dirty work and custody. A quota reset or a green comparator
never grants a claim, replays a session or authorizes publication.

Stokowski coordinates local-ready mode. An active Morgan session coordinates
cloud fallback only through qualified claims and fences. Foo remains the claim
authority for this rollout; unavailable authority holds new claims, transfers
and dependent effects. Morgan absence holds new fallback admission. An explicit
stop remains effective across quota changes. No unattended cloud wake-up is
promised. Native runtime integration and installed adoption require separate
verified evidence; source tests and documentation are not deployment proof.

Before Foo access read [current Windmill routing](docs/agents/windmill-workspace.md).
Cloud checkouts are isolated from Foo and from other workers. Use actual tools,
grants and shared resource admission; root transport does not imply repository
commands should run as root. Never bypass denied access through another route.

Use the [managed supervision skill](.agents/skills/uif-supervision/SKILL.md) for
service reports and supported controls. Keep project-specific skill/plugin
capabilities and [memory routing](docs/agents/memory-routing.md) scoped. Load
historical adoption/source records only for their applicable evidence, preserving
current holds and accepted work. Documentation changes do not start, stop,
reconfigure or repair live services.
