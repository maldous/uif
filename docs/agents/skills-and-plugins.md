# Skills, plugins and execution capabilities

This is the policy 2.0.0 capability map, not an installation manifest. Discover
actual tools and granted scopes in each environment; names in a registry or a
skill do not prove availability, authorization, deployment or successful work.
Load only the relevant skill and contained references for the selected task.

## Shared operational capabilities

| Capability | Correct use and evidence |
| --- | --- |
| UIF supervision | Normal full-token start/stop/report and read-only supervision; apply the policy's distinct active-Morgan fallback role during token exhaustion. A skill update and actual environment adoption must be verified separately. |
| GitHub/native Git | Read source and review/merge outcomes; project owners may use native Git in their own environment. Preserve current branch/source, publication controls and one integration writer. |
| Native Linear | Sole live issue intake, dependencies, scope, acceptance and durable coordination. Read immutable workspace/project/issue identity; comments/status are not atomic claims. |
| Foo Workspace MCP | Discover workspace, script schema, current revision and terminal run receipts. Use the supported user/root execution route for deterministic commands with explicit host/project/source bindings. |
| Foo root jobs guidance | Privileged host-transport rules, immutable job identity and reconciliation. The fixed wrapper may have a stale workspace/disabled label; do not invoke it based on the generic connector's availability. |
| Foo Codex controls | Use only the supported session-control interface actually exposed to its authorized owner. MCP shell execution is not an implied grant to create/resume sessions. |
| LangChain/LangGraph | Use only the workflow/persistence actually selected by the project. Bind compatible checkpoint/source/stage/claim/operations; do not introduce another queue or assume hosted products are required. |
| Assistant collaboration | Finite independent reasoning or exact-candidate review within an existing role. These subagents are not additional durable cloud roles or Foo Codex sessions. |

A required capability missing from a selected lane blocks that dependent step.
Use another already-authorized independent lane only after ownership and earlier
effects are reconciled. Do not bypass a denial, invent an endpoint, install
credentials or weaken host/security controls to make a capability appear present.
No new paid provider, plugin installation or recurring automation follows from
this inventory.

## Update and adoption responsibility

UIF maintains shared execution rules and their inventory. Project owners maintain
product skills, SDK/MCP catalogs and the source contracts they describe. Update
an affected skill with its source/interface change through the existing reviewer
and publisher. Preserve license/provenance files and frozen historical copies.

For a tool or skill change record the exact source/package, supported schema,
rights, selected environment and checks. Separately verify installation and
actual execution where authorized. Do not claim that advisory prompt text, a
plugin listing, source merge or offline check enforces all prose at runtime.

These identifiers name requirements to verify at execution time. They are not
claims that an installed connector implements them.

| Foo MCP root | `verified-connector-schema`, `verified-foo-host`, `specific-host-authorization`, `shared-resource-admission`, `original-operation-receipt` | `bounded-host-configuration` |

Resource admission applies to the actual resource-consuming command, including
root transport and repository commands demoted to the checkout owner; a bounded
status read does not reserve an unrelated model session or build allocation.
