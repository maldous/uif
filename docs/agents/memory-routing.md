# Memory and evidence routing

Policy 2.0.0 uses existing canonical stores. The namespaces in
[environment-profiles.json](environment-profiles.json) are routing labels for
approved environment memory, not new databases, queues or proof that any memory
service is installed. If no approved memory surface exists, keep references in
the existing issue/handoff rather than creating one.

| Information | Durable home |
| --- | --- |
| Live issue scope, dependencies, acceptance, material decision/blocker, owner transfer and next action | Existing native Linear issue/project with verified destination readback. |
| Reviewed source, product contracts, tests, skills and documentation | Owning Git repository at the exact branch/commit under its existing publisher/reviewer controls. |
| Claim generation/coordinator epoch, execution ownership and fenced transfer | Qualified off-Foo control authority, independently available during Foo/MCP outages. Its adapter is currently unimplemented; it is not an intake queue or a substitute for Linear. |
| Job intent, original operation ID, terminal receipt, outputs and stopped-child evidence | Existing authorized executor receipt store; Linear receives suitable references. |
| LangGraph checkpoint | Selected workflow's existing private persistence with code/schema/source/stage compatibility and claim/operation links. |
| Reusable non-secret operating fact | Owning role's approved `uif/roles/<role>` namespace, or `uif/shared` only after cross-project applicability is reviewed. |
| Secrets, credentials, raw datasets, customer configuration and private message bodies | Their existing protected custody; never these memory namespaces, public Git, shared prompts or exported handoffs. |

Keep facts small and sourced: observation time, exact source/evidence link,
applicability, owner and stale/superseded status. Mutable process state, counts,
allowance and deployment revisions require fresh evidence before use. Memory
cannot grant access, release a hold, declare a claim expired or prove execution.

Role memory stays scoped to its project. CIX public product and private operations
have separate disclosure boundaries even though they share a logical role. Put
only an allowlisted non-secret lesson or opaque reference into shared memory;
keep private histories and raw results with their actual custodian. No household
message content or credentials are imported into UIF operational memory.

Read the applicable policy/profile and project instructions before using saved
context. Prefer current source, Linear and original receipts when they conflict
with an old summary. Mark the correction with its evidence rather than rewriting
historical receipts. A parent-provided summary or local path does not transfer a
file or prove a child loaded it.

At a handoff preserve source/branch/HEAD, claim generation, completed and uncertain
operations, custody references, checks/review and the first unaccepted next stage.
Remote source readback establishes publication; acknowledgments establish receipt;
actual subsequent work establishes execution. Keep those claims separate.

Coordinator lifecycle registration, desired running/stopped state, epoch/lease,
qualified liveness/failure-grace observations and original appointment operation
belong to that authority and its approved durable scheduling surface, not chat
memory. A replacement reconstructs the same Morgan/project role and original
operations. No conversation's continued existence is a recovery dependency.
