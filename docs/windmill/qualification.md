# Foo-only Windmill configuration and offline recreation

The connected Foo Workspace OAuth account exposes workspace `foo`. Shared
bindings select `foo` at
`https://windmill.aldous.info/api/mcp/w/foo/mcp`. The private root connector,
neutral runner and credential consumer still need qualification in that
workspace. The repository declares the target and runs offline checks.
Dated receipts preserve the prior workspace and connector observations.

## Run from a clean checkout

Python 3.12 standard library only; no package installation, provider call, SSH,
credential access, Windmill SDK, subprocess, service restart or shell execution.

```
python3 -m unittest discover -s tests/windmill -v
python3 -m unittest discover -s tests/white_room -v
python3 tools/windmill/white_room.py validate
python3 tools/windmill/white_room.py plan
python3 tools/windmill/white_room.py recreate-mock --output /tmp/foo-test-new-directory
```

The mock command requires a nonexistent output directory and writes a local
SQLite test workspace plus an explicitly synthetic receipt. A second client reads
the persisted job ID without resubmission. Requests accept only an identity probe
or same-ID status; this is deliberately a test contract, **not asserted equivalence
to the deployed command/cwd/timeout interface**. Unknown fields and invalid IDs
fail before credential resolution. A synthetic opaque credential handle is passed
to a mock SSH transport; there is no real secret input or output. Adapter exceptions
and unexpected identity responses cannot produce successful terminal receipts.

A local SQLite transaction serializes admission by job ID. Before a mock effect,
the job is committed as uncertain. Interruptions retain that state; retries/status
never replay an uncertain effect. This models recovery safety but is not a live
cross-host lease/fencing implementation. The isolated database is not a Windmill
server and its receipt cannot qualify actual host recovery or SSH permissions.

## Migration and rollback

The executable `plan` command reports an ordered, non-executing plan and blockers.
One authorized migration owner must reconcile host jobs and consumers, preserve
recoverable source/config in approved custody, qualify source/schema pins, obtain
required credential/access confirmations, use approved disposable custody, and
verify fresh-child identity plus same-job status and terminal receipt. Only then
can reviewed consumers switch. Do not infer readiness from an empty Windmill queue.

Retain historical workspace resources, credential bindings and recoverable
configuration throughout qualification. Keep UIF paused if qualification fails.
If a later authorized switch fails, reconcile original operation outcomes
before restoring exact reviewed preimages. Restore source
only from verified custody, never an unverified inventory. Do not automatically
re-enable disabled project schedules. Permanent removal requires exact action-time
confirmation and is absent from all executable code here.

The observed server/16-worker topology is not a declaration of the user's intended
eight instances. Biscoe/Fab identity, source qualification, native-job reconciliation,
new credentials/access, live restore and fresh-child end-to-end verification remain
open. These gaps do not block independent source-only cloud validation.


## Supported REST recreation adapter and actual source custody

`tools/windmill/recreate.py` implements the official Windmill REST sequence through
an injected authenticated transport. `config/windmill/api-contract.json` contains
selected verbatim definitions from upstream commit
`5d3f239bf2c114ffe0215eebd1cc5fca38435c90`, API version 1.864.1. This upstream version
has not been matched to deployed Foo; compatibility qualification is still required.
The tests use a local HTTP fake server and synthetic source fixtures, never Foo.

The adapter requires an explicit isolated target ID (offmenu/admins are forbidden),
a reviewed source export, source/schema/resolved-lock SHA-256 pins, and a separately
authorized external credential-binding callback. No credential value is an adapter
argument. It uses POST /api/workspaces/exists and /create, checks variable existence,
POSTs /api/w/{workspace}/scripts/create without parent_hash, then reads the deployed
script by path to compare source/schema/lock and returned version hash. It never
executes the source, grants roles, creates credentials, updates an existing script,
retries an uncertain write, deletes anything or switches the current MCP endpoint.

An exclusively created, fsynced journal fences automatic duplicate recreation.
An uncertain or partial attempt remains pending for reconciliation; it is not
rolled back by deleting a workspace. A successful script-copy-verified receipt is separate
from the original journal and still sets live_recreation_verified=false,
permissions_verified=false and host_protocol_verified=false. It certifies only the
supplied source/schema/lock copy and returned version identity, not role completeness. This is
not a complete live runtime qualification or proof of least-privilege permissions.
There is no live CLI or built-in production transport; an approved caller supplies
request(method, API path, JSON body) returning (status, decoded body), with auth and
permission confirmation handled externally. Test LocalTransport is loopback-only.

The checked-in deployment bundle deliberately cannot currently deploy: the MCP
source read supplied exact Python source and schema but omitted resolved lock and
Windmill version hash. The lock pin is null and fails before API calls. Source
requirements pin paramiko==5.1.0 and wmill==1.850.0; those are declarations, not a
resolved transitive dependency lock. Obtain the actual nonsecret resolved lock
through a supported, authorized export before using the adapter. Do not substitute
an empty lock or a hash of the mock. The public SSH host-key pin is not a private
credential. The historical source docstring/summary says disabled while its actual
ENABLED=True constant is preserved; provenance records this discrepancy.

`tests/windmill/test_exported_runner.py` loads the exact preserved runner with
synthetic wmill/paramiko modules only. It verifies invalid requests reject before
credential lookup, pinned SSH mode, same-ID status requests, and wrong-ID receipt
rejection. It does not claim remote durable state, sanitization of arbitrary command
output, host-script correctness, or a successful real SSH connection. The separate
SQLite model tests uncertain-effect recovery and concurrent admission as a model.

## Publication and environment limits

UIF develop 62bd808ba03528288bb5e395ba319fb54b32a99f. A standard GitHub clone was

SQLite fixtures alone provide no durability guarantee.


### Preserved deployed-source security findings

Independent mock review of the exact custody export found that an exception from
wmill.get_variable can propagate arbitrary exception text, and a receipt with valid
version/job_id/status can contain arbitrary extra output fields that are returned
unchanged. The export is therefore **not qualified as a secret-safe replacement**.
Preserve its exact bytes as evidence; a separately reviewed candidate must address
these findings before runtime acceptance. Source/schema hashes prove identity, not
safety. The adapter rejects an empty/blank lock for this dependency-using runner,
but a nonempty hash alone still does not prove that a lock is a genuine resolution.

The active transport is `foo`. The `recreation_workspace` selector remains
unset until the owner chooses an isolated target for an authorized recreation.
The active workspace is never selected by the offline mock. The generic Foo
root identity readback established host and effective identity only.
